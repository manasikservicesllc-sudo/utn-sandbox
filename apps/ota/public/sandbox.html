02 / PAYLOAD CONTRACT

A familiar body. A purposeful extension.

The request preserves groupInfo, package and mutamers from the supplied OTA B2C guide v1.4.6, section 5.16. Use additionalInformation for OTA-only context. Send these groups directly at the root; no visaRequest wrapper is needed.

Group What it contains
groupInfo OTA, request, group, operator and external agent references
package Arrival, departure, ground services, housing, transport and enrichment
mutamers[] Names, passport, residence, nationality, contact and original disclosure fields
additionalInformation Optional booking context, notification mode and configured callback URL

04 / RESULTS & CALLBACKS

Results you can reconcile.

GET {baseUrl}/v1/verification-requests/{id}

Each traveler has an independent verification result. Assessment outcomes are verified, needs_review or rejected. Corrections return the assessment to pending. Only verified assessments receive a credential.

Configure a callback URL and a separate signing secret with your operator. A requested additionalInformation.callbackUrl must match that configured URL exactly. Missing configuration is reported as not_configured. 

{
  "eventId": "<event-id>",
  "requestId": "<request-id>",
  "bookingId": "<booking-id>",
  "invitationId": "<invitation-id>",
  "otaMutamerId": 1,
  "verification": { "status": "verified", "revision": 1, "mode": "demo", "simulated": true }
}

Envelope illustration; the actual verification includes checks, concerns, scope and any certificate.

Verify before applying.

Read x-utn-timestamp and x-utn-signature. Verify hex HMAC-SHA256 of timestamp + "." + rawBody with the callback secret. Allow a five-minute clock window, compare in constant time, deduplicate eventId, and apply only a newer per-invitation revision.

Failed configured callbacks are queued for retry. Polling the GET endpoint remains available for reconciliation. The credential is a signed UTN prototype assessment, not a government certificate or public-key attestation.

05 / SANDBOX TESTS

Prove the whole round trip.

  1. Create one traveler, open the invitation and run a simulated verified result.
  2. Verify one traveler in a group and confirm the others remain independent.
  3. Exercise review and rejected outcomes; confirm no verified credential appears.
  4. Replay the same idempotent request; changing its body should return 409.
  5. Correct traveler details and confirm invalidation of the previous result.
  6. Try AI without configuration: expect 503, never a simulated fallback.
  7. In protected mode check invalid keys; in both modes check oversized images, expired invitations and disallowed callback URLs.
  8. Replay and tamper with callbacks; confirm deduplication, revision ordering and signature checks.
